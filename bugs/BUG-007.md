# BUG-007: Отсутствует механизм навигации из OnboardingScreen в MainScreen с очисткой back stack

**Автор:** QA Tester
**Дата обнаружения:** 2026-03-14
**Связанная задача:** TASK-005
**Ветка/PR:** feature/TASK-005-navigation / PR #4
**Критичность:** High

---

## Описание

В fix-коммите `110409e` (fix BUG-005) при замене `OnboardingScreen` на Text-placeholder был удалён обработчик навигации `onOnboardingCompleted` вместе с вызовом:

```kotlin
navController.navigate(Screen.Main.route) {
    popUpTo(Screen.Onboarding.route) { inclusive = true }
}
```

В результате маршрут `Screen.Onboarding.route` в `AppNavGraph.kt` отображает только статический текст без какой-либо возможности перейти на `Screen.Main`. Архитектурное требование TASK-005 — "После онбординга: `popUpTo(Screen.Onboarding.route) { inclusive = true }` — очищает back stack" — не выполнено.

При интеграции с TASK-004 (`OnboardingScreen`) разработчик не сможет передать callback `onOnboardingCompleted` в навигационный граф, поскольку сигнатура `composable`-лямбды его не принимает. Это заблокирует функцию перехода из онбординга в основной экран.

## Шаги воспроизведения

1. Открыть файл `android core/app/src/main/java/com/example/localguide_planner/ui/navigation/AppNavGraph.kt`
2. Найти блок `composable(route = Screen.Onboarding.route)`
3. Убедиться: внутри блока отсутствует параметр `onOnboardingCompleted` и вызов `navController.navigate` с `popUpTo`
4. (После интеграции TASK-004) Запустить приложение с DataStore где онбординг не пройден — пользователь попадёт на экран онбординга и не сможет перейти далее

## Ожидаемый результат

Согласно TASK-005, acceptance criterion:

> "После онбординга: `popUpTo(Screen.Onboarding.route) { inclusive = true }` — очищает back stack"

`AppNavGraph.kt` должен содержать в маршруте `Screen.Onboarding.route` параметр-лямбду `onOnboardingCompleted`, которая вызывает:
```kotlin
navController.navigate(Screen.Main.route) {
    popUpTo(Screen.Onboarding.route) { inclusive = true }
}
```

## Фактический результат

Маршрут `Screen.Onboarding.route` содержит только `Text(text = stringResource(R.string.placeholder_onboarding))`. Навигационная логика полностью отсутствует. Тест-сценарий #4 из TASK-005 не может быть выполнен.

## Скриншоты / Видео

## Возможная причина

При исправлении BUG-005 (замена `OnboardingScreen` на placeholder) разработчик удалил не только ссылку на `OnboardingScreen`, но и весь блок логики навигации `onOnboardingCompleted`. Правильное решение — сохранить параметр-лямбду в сигнатуре placeholder-а или передать его как заглушку `{}`, оставив структуру `popUpTo` нетронутой до интеграции TASK-004.

## Для Developer (заполняется при фиксе)

**Корневая причина:**

**Описание фикса:**
Восстановить параметр `onOnboardingCompleted: () -> Unit` в маршруте Onboarding внутри `AppNavGraph.kt`. Структура должна быть:

```kotlin
composable(route = Screen.Onboarding.route) {
    // Placeholder — будет заменён на OnboardingScreen после мержа TASK-004
    // Callback сохранён для корректной интеграции
    Text(
        text = stringResource(R.string.placeholder_onboarding),
        modifier = Modifier.clickable {
            navController.navigate(Screen.Main.route) {
                popUpTo(Screen.Onboarding.route) { inclusive = true }
            }
        }
    )
}
```

Либо, более чисто — добавить лямбду в параметры `AppNavGraph`:
```kotlin
@Composable
fun AppNavGraph(
    startDestination: String,
    onOnboardingCompleted: (NavController) -> Unit = { nc ->
        nc.navigate(Screen.Main.route) {
            popUpTo(Screen.Onboarding.route) { inclusive = true }
        }
    }
)
```
