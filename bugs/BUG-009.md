# BUG-009: Необработанное исключение в OnboardingViewModel.onGetStartedClicked приводит к крэшу и зависанию isLoading

**Автор:** QA Tester (переименован Orchestrator: BUG-005 → BUG-009 во избежание конфликта нумерации)
**Дата обнаружения:** 2026-03-14
**Связанная задача:** TASK-004
**Ветка/PR:** feature/TASK-004-onboarding / PR #5
**Критичность:** Critical

---

## Описание

В методе `onGetStartedClicked()` класса `OnboardingViewModel` вызов `saveUserProfileUseCase(...)` выполняется внутри `viewModelScope.launch` без обёртки `try/catch`. Если `saveUserProfileUseCase` бросит исключение (например, `IOException` при записи в DataStore), произойдёт следующее:

1. Строка `_uiState.update { it.copy(isLoading = false) }` не выполнится — `isLoading` навсегда зависнет в `true`, спиннер не исчезнет, кнопка «Начать» не вернётся.
2. Необработанное исключение в `viewModelScope` без кастомного `CoroutineExceptionHandler` приведёт к крэшу приложения.

Соответствующий блок кода (`OnboardingViewModel.kt`, строки 47–52):

```kotlin
viewModelScope.launch {
    _uiState.update { it.copy(isLoading = true) }
    saveUserProfileUseCase(UserProfile(name = name, isOnboardingCompleted = true))
    // Если строка выше бросает исключение — следующие две строки не выполняются
    _uiState.update { it.copy(isLoading = false) }
    _uiEffect.emit(OnboardingUiEffect.NavigateToMain)
}
```

## Шаги воспроизведения

1. Запустить приложение.
2. Подготовить мок `SaveUserProfileUseCase` так, чтобы он бросал `RuntimeException("DataStore write failed")`.
3. На экране онбординга ввести корректное имя (например, «Алексей»).
4. Нажать кнопку «Начать».

## Ожидаемый результат

- При ошибке UseCase `isLoading` сбрасывается в `false`.
- Пользователю показывается сообщение об ошибке, экран остаётся работоспособным.
- Приложение не крэшится.

## Фактический результат

- `isLoading` остаётся `true` — UI заморожен: спиннер крутится бесконечно.
- Необработанное исключение вызывает крэш приложения.

## Среда воспроизведения

- **Android API:** minSdk 24 — targetSdk 36
- **Версия приложения:** versionCode 1 / versionName 1.0

## Дополнительные замечания (Medium)

1. **Отсутствует тест граничного случая**: имя ровно в 50 символов должно успешно проходить валидацию — теста нет.
2. **Отсутствует тест на поведение при исключении UseCase**: нет unit-теста, проверяющего что `isLoading = false` при ошибке.
3. **Тексты строк в strings.xml не соответствуют спецификации TASK-004.md**:
   - `onboarding_title`: `"Добро пожаловать в LocalGuide"` вместо `"Добро пожаловать!"`
   - `onboarding_name_error_empty`: `"Введите ваше имя"` вместо `"Введите имя"`
   - `onboarding_name_error_too_long`: `"Имя слишком длинное (максимум 50 символов)"` вместо `"Имя не должно превышать 50 символов"`

## Для Developer (заполняется при фиксе)

**Корневая причина:**

**Описание фикса:**
1. Обернуть `saveUserProfileUseCase(...)` в `try/catch` (или `runCatching`) с `finally { _uiState.update { it.copy(isLoading = false) } }`
2. При исключении: логировать ошибку, при необходимости показать пользователю (можно добавить `errorMessage` в UiState)
3. Добавить unit-тест: исключение из UseCase → isLoading = false
4. Добавить unit-тест: имя ровно 50 символов → проходит валидацию
5. Исправить тексты строк в strings.xml согласно TASK-004.md
