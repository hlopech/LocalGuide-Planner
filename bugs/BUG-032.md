# BUG-032: PlacesSearchBar хранит локальное состояние `active` вне ViewModel

**Автор:** QA Tester
**Дата обнаружения:** 2026-03-21
**Связанная задача:** TASK-014
**Ветка/PR:** feature/TASK-014-search-and-filters / PR #16
**Критичность:** Medium

---

## Описание

В composable-функции `PlacesSearchBar` (`PlacesListScreen.kt`, строка 255) объявлена локальная переменная состояния:

```kotlin
var active by remember { mutableStateOf(false) }
```

Это нарушает принцип stateless Composable, закреплённый в `CLAUDE.md`: «Composable-функции stateless (состояние в ViewModel)». Состояние `active` (развёрнут/свёрнут SearchBar) хранится в Composable, а не во ViewModel, что означает:

1. При пересоздании Composable (например, при смене конфигурации) состояние активности поиска будет потеряно.
2. Невозможно протестировать это состояние через unit-тесты ViewModel.
3. Нарушение архитектурного соглашения проекта.

## Шаги воспроизведения

1. Открыть экран списка мест.
2. Тапнуть на SearchBar — он становится активным (`active = true`).
3. Повернуть устройство (смена конфигурации / пересоздание Activity).
4. Наблюдать результат.

## Ожидаемый результат

Состояние `active` SearchBar должно управляться через `PlacesListUiState` и `PlacesListViewModel`, либо сохраняться через `rememberSaveable` для переживания смены конфигурации.

## Фактический результат

При пересоздании Composable состояние `active = false` сбрасывается, SearchBar закрывается даже если пользователь вводил текст.
