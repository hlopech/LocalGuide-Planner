# BUG-037: Side effect внутри лямбды combine в ProfileViewModel

**Автор:** QA Tester
**Дата обнаружения:** 2026-03-21
**Связанная задача:** TASK-015
**Ветка/PR:** feature/TASK-015-profile-screen / PR #17
**Критичность:** Low

## Описание

В `ProfileViewModel.kt` строка 40 содержит side effect (запись в `MutableStateFlow`) внутри трансформационной лямбды оператора `combine`:

```kotlin
val uiState: StateFlow<ProfileUiState> = combine(
    getUserProfileUseCase(),
    getPlacesUseCase(),
    _editedName,
    _isSaving,
    _showResetDialog,
) { profile, places, editedName, isSaving, showDialog ->
    _latestProfile.value = profile   // строка 40 — side effect внутри combine!
    ...
    ProfileUiState(...)
}
```

Лямбда `combine` должна быть чистой функцией преобразования (pure transform). Запись в `_latestProfile` внутри неё нарушает этот принцип: лямбда вызывается на фоновом потоке и может вызываться несколько раз (при переподписке), что приводит к непредсказуемым побочным эффектам при конкурентном исполнении.

Корректная альтернатива — добавить `_latestProfile` в список источников `combine` или использовать `onEach`/`map` для отдельного сохранения профиля.

## Шаги воспроизведения

1. Открыть `ProfileViewModel.kt`.
2. Строка 40: `_latestProfile.value = profile` внутри лямбды `combine`.

## Ожидаемый результат

Лямбда `combine` — чистая функция без side effects. Сохранение последнего профиля должно выполняться вне трансформационной лямбды.

## Фактический результат

Side effect в лямбде `combine`: запись в `MutableStateFlow<UserProfile?>` внутри трансформационного оператора.

## Возможная причина

Разработчику нужен был доступ к последнему значению профиля в методе `saveProfile()`. Вместо добавления `_latestProfile` в список источников `combine` или использования `stateIn` с `WhileSubscribed`, значение сохраняется через side effect.
